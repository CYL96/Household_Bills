# Android WebView 客户端与 APK

## 背景与目标

为现有家庭账本增加可安装的 Android 客户端。首次进入配置服务器地址，后续可在 App 设置页更换；设置入口不能遮挡网页已有导航、记账按钮和弹窗。

## 实际变更

- 新增独立 `android/` 原生 Java 工程，包名 `com.household.bills`、应用名「家庭账本」、版本 `1.0.0` / `versionCode=1`。最低 Android 8.0（API 26），编译与目标 API 35；AGP 8.9.2、Gradle Wrapper 8.11.1、JDK 17。无第三方运行时依赖，只有 JUnit 4 测试依赖。
- `MainActivity.java` 提供首次配置、应用设置、WebView 和原生错误页面。页面顶部独立占位 48dp 工具栏，账本状态右侧显示「设置」，不使用悬浮按钮。状态栏、导航栏、刘海与输入法 Insets 由原生容器处理，设置/错误页面隐藏底层网页，避免其表单进入无障碍焦点。
- `ServerAddress.java` 负责纯 Java 地址解析：接受 HTTP/HTTPS 根地址和端口、省略协议时使用 HTTPS；规范化大小写、默认端口、IPv6 与末尾斜杠，去除首尾空白；拒绝用户名密码、查询参数、锚点、页面路径、内部空白、反斜线和非法端口。地址保存在应用私有 SharedPreferences。
- 修改地址前确认；保存同一地址不清 Cookie。更换 origin 时持久记录待清理状态，停止接收 Cookie、关闭旧页 JavaScript，等待空白文档完成导航后销毁旧 WebView，再清理 Cookie、网页存储、缓存与历史，创建新实例加载新服务器。进程或配置变更中断后会先完成待清理工作；旧实例回调用实例与 generation 校验隔离。
- WebView 开启 JavaScript、DOM Storage 与第一方 Cookie，关闭第三方 Cookie、文件/内容访问与混合内容；不注入 JavaScript 原生桥。站内链接留在 WebView，外站 HTTP(S) 链接交给浏览器，其它 scheme 不加载。HTTPS 证书错误始终取消，无忽略入口。
- 主文档网络错误、HTTP 错误、TLS 错误有原生提示和「重试」「设置」；子资源/API 错误不替换整页。返回键处理设置取消、错误页和站内历史；切换后不保留旧站点返回栈。设置草稿及错误详情随旋转恢复。
- 新增 `ServerAddressTest.java`，覆盖合法局域网地址、规范化、SPA URL 的 origin，以及不安全/不可部署地址的拒绝。更新根 README 的 Android 安装、连接、构建与签名使用说明，并排除 Android 生成物和私钥文件。
- 前端与后端业务代码未修改；APK 直接加载现有站点，不包含服务器或离线数据副本。

## 验证结果

### 构建与签名

- 使用 JDK 17、Gradle 8.11.1 和 Android SDK 35 执行 `:app:testReleaseUnitTest :app:assembleRelease`，最终签名构建成功；Release 构建附带的 lint vital 检查通过。NixOS 本机通过命令行指定 Nix 兼容的 `aapt2`，并为依赖下载设置本机代理，未把这些机器路径或代理写入项目配置。
- 永久地址单元测试：4 项，失败 0、错误 0、跳过 0。另执行 throwaway Java 地址烟测：7 个合法样例、17 个拒绝样例及协议/origin 边界通过。
- `apksigner verify --verbose --print-certs` 验证通过；最终 APK 使用 APK Signature Scheme v2 签名。ADB 安装、启动成功；`run-as` 被拒绝，证明交付包不可调试。`aapt dump badging` 确认 API 26 / target 35、版本号、应用名与仅有 INTERNET 权限。

### Android 15 模拟器实测

使用 API 35 x86_64 模拟器，手机视口 390×844dp（780×1688 像素），通过 ADB 操作、UI 层级与截图观察：

- 清空应用数据后首次进入设置，填写服务器根地址后加载现有真实账本服务的登录页；包含 `/api` 的错误地址被拒绝。
- 顶部「设置」、当前地址回填、「取消」返回网页、进程退出再打开保留地址通过；网页登录输入框弹出键盘时容器缩小，顶部入口与表单未被键盘覆盖。
- 隔离 HTTP 验收站点的持久 HttpOnly Cookie 和 JavaScript Cookie 在进程重启后保留；保存同一服务器地址不清 Cookie。
- 旧站点持续每 10ms 写 Cookie 的情况下，从同一主机的端口 A 切到端口 B，新站点首次请求不带旧 Cookie；切换后系统返回键直接退出，不访问旧站点。
- 主文档 HTTP 503 显示原生错误；进入设置后旋转并取消，HTTP 503 详情仍保留；重试返回配置的根地址。
- 不可连接的端口显示原生错误及重试/设置；启动该端口的服务后点击重试，成功显示恢复页面。
- 指向隔离自签名 HTTPS 服务，显示「证书校验失败」，没有加载不可信正文或提供绕过选项；可从错误页设置切回真实账本服务。

验收期间发现并修正两个运行时问题：仅调用 `destroy()` 不能保证旧渲染进程立即停止写 Cookie，因此改为停止 Cookie 接收并等待空白文档完成后再清理；HTTP 错误可能早于 `onPageStarted()` 到达，因此同源主框架导航在允许加载时就更新目标 URL，避免丢失错误回调。

未执行 Android 真机、多厂商机型或 API 26–34 的运行验证；未使用真实账号登录或提交业务数据，未验证登录后底部导航、全屏记账弹窗、外部浏览器跳转及所有生命周期时序。未运行前后端广泛回归套件或前端构建，业务代码未改动。

## 兼容性与迁移

- 服务器必须是手机能访问的完整站点根地址；不能把电脑的 `localhost` 或 `/api` 地址填入 App。当前只监听 `127.0.0.1` 的服务需配置 HTTPS 反向代理，或自行按可信局域网需求调整监听与防火墙；本任务未更改现有服务的暴露范围。
- 推荐有效 HTTPS 证书，只信任系统 CA；不支持绕过自签名/过期/域名不匹配证书。可信内网使用 HTTP 时，服务端需设置 `COOKIE_SECURE=false`；不能以此替代公网 HTTPS。
- 登录 Cookie 过期或服务端注销仍按原网站规则生效。更换服务器只清本 App 的本地站点状态，不删除账本或撤销其它设备的登录。
- APK 是轻量 WebView 壳，手机需安装并更新系统 WebView。网页更新由服务器提供；APK 不必随每次网页改动重发。
- 本次签名私钥与密码保存在本机构建用户的 `~/.local/share/household-bills/android-signing/`，权限受限，不在仓库内。后续维护者必须安全备份该目录，使用同一密钥并递增 `versionCode` 才能覆盖升级；更换签名需卸载旧包，会清除 App 本地地址与登录状态。禁止提交私钥或密码。
- `app/build/` 是忽略的构建输出，本次交付 APK 已实际生成；在其它机器拉取源码后应按 README 重新构建并配置自己的签名。

## 后续更新：设置页刷新页面缓存（1.0.1）

### 背景与实际变更

服务端更新 UI 后，需要在 App 设置内主动清理旧页面资源并重新拉取，不应为此退出登录或重新填写服务器。

- 在原生设置页「取消」下方增加独立「页面缓存」区块、用途说明和「刷新页面缓存」按钮，沿用已有按钮与滚动布局；首次尚未保存服务器时不显示，切换服务器清理期间不可点击。
- 点击后停止当前加载、取消网页 JavaScript 对话框，调用 `WebView.clearCache(true)` 清理内存/磁盘资源缓存，再加载已保存服务器的根地址。主文档附带 `Cache-Control: no-cache` 和 `Pragma: no-cache` 请求头；后续子资源因本地缓存已清而重新请求，不永久禁用正常缓存。
- 不清 Cookie、DOM Storage、服务器配置或服务器数据，不读取或保存地址输入框草稿；刷新导致当前网页文档重新加载，尚未提交的网页表单需要事先保存。网络、HTTP、TLS 错误继续走现有原生错误页。
- APK 升级为 `1.0.1` / `versionCode=2`，沿用首次交付签名，可覆盖安装；前后端业务代码未改动。根 README 同步操作路径和刷新范围。
