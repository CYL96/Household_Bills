# 分类拖动排序挤压效果

## 背景与目标

分类管理中的一级分类在拖动期间禁用了排序过渡，子分类网格未启用排序过渡。目标是让同级分类在拖动换位时平滑让位，避免瞬间跳动。

## 实际变更

- 一级分类拖动时保留 Vue `TransitionGroup` 的移动过渡；子分类网格也使用相同过渡，相邻项以 0.22 秒的位移动画滑动让位。
- 保留拖动项已有的放大、高亮和阴影反馈；删除不再使用的拖动期间禁用动画样式及排序标记。
- 在手势激活时记录分类卡片的布局槽位，使用不受过渡变换影响的布局偏移，而不是逐帧读取动画中卡片的屏幕矩形；落点按当前同级草稿顺序映射，避免动画干扰造成反复换位。
- 落点坐标仍随容器滚动换算；鼠标拖动、触摸长按、取消回滚、键盘排序以及点击“保存设置”后持久化的流程不变。
- 继续遵守减少动态效果的系统设置，在该模式下禁用过渡。

## 验证结果

- 在 `frontend/` 执行 `npm run build` 通过，包含 `vue-tsc --noEmit` 类型检查和 Vite 生产构建。构建提示部分产物超过 500 kB，未阻断构建。
- 执行临时 Node.js 手势冒烟脚本，通过 TypeScript 编译器提取并运行组件中的实际拖动函数，使用模拟的布局元素验证：
  - 一级分类跨网格行前移、后移；同一落点连续处理 12 次保持顺序稳定。
  - 容器滚动改变屏幕位置后，落点仍能正确排序；取消拖动完整恢复原草稿。
  - 触摸长按激活子分类拖动，只调整同级子分类，松手保留新顺序。
  - 触摸在长按激活前移动，取消排序，不影响正常滚动手势。
  - 所有检查通过；临时脚本已移除。
- 未进行浏览器页面展示或交互视觉验证，遵守仓库约定；实际动画观感仍需用户在页面确认。上述冒烟检查验证排序逻辑，不证明真实浏览器的动画渲染效果。
- 未运行后端测试，本次不涉及后端。

## 兼容性与迁移

仅调整前端排序动画与落点计算，不新增依赖，不修改 API、分类存储结构或数据库，无需数据迁移。排序仍限于原有同级分组，拖动仍只修改草稿。
