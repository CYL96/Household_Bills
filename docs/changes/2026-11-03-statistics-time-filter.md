# 统计报表年月与时间段筛选

## 背景与目标

统计页在原账户、用户组合筛选基础上，增加按年、按月切换和自选时间段；默认按月，分类下钻与流水明细沿用主页条件。日期控件保持只读，避免重现 Android WebView 点击日期时弹出键盘的问题。同期用户选项移除管理员，详见[账户与用户筛选记录](2026-11-03-statistics-account-filter.md)。

## 实际变更

- `ReportsView.vue` 增加“按月 / 按年 / 时间段”分段切换。按月选择月份，按年选择年份，时间段分别选择开始和结束日期，默认当前月首末日。各模式记住自身选择，切换时保留账户与用户。
- 时间段使用两个单日历面板，避免双月范围面板在手机上过宽；前端禁止开始晚于结束，允许选择同一天。月份、年份、开始和结束控件全部 `editable=false`、`clearable=false`。
- 统一时间查询与中文时间标签，覆盖总额、环形图无障碍文案、大小类、二级分类、明细副标题、加载提示和空状态。时间或账户变化重置下钻并重新加载；用户或收支变化仅重置下钻，仍保留刷新与异步序号保护。
- 全年查询一次加载，不拼接 12 次月份请求。账户继续由服务端过滤，用户继续按流水 `owner` 对加载结果取交集，转账不计收入或支出。
- 手机下收支、时间模式、日期、账户/用户各成一行，账户与用户仍并排；时间段起止输入等宽并排。仅为报表日期弹层增加专用样式，缩小固定宽度面板及内部内容，修复 320px 视口打开日历后横向溢出，不隐藏或裁切内容。
- API 查询类型、请求封装和中文错误字段标签增加 `start`、`end`；本地日期辅助工具不经 UTC 转换，保留本地民用日期语义。总览和流水页仍按原月份交互使用。
- `README.md` 更新简短的统计能力介绍。

## 接口与兼容性

`GET /api/transactions/` 新增 `start=YYYY-MM-DD&end=YYYY-MM-DD`，首尾两天全天均包含。日期必须严格有效且成对提供，结束不得早于开始，不能与 `month` 同时使用；非法输入返回中文字段数组及 HTTP 400。

服务端将日期转换为 `[start, end + 1天)`，复用已有流水 SQL 的半开区间和家庭隔离，不改变表结构、返回结构或原有账户、类型等筛选。原 `month=YYYY-MM` 和未传时间参数的行为保留，无数据库迁移。
