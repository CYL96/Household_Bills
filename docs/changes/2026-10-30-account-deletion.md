# 账户删除

## 背景与目标

账户原先只有新增和编辑功能，需要补充删除入口，同时避免删除账户时连带丢失历史收支和转账流水。

## 实际变更

- 在账户编辑窗口底部增加“删除账户”按钮，新增账户时不显示。删除前二次确认，说明操作不可恢复、仅无流水账户可以删除，以及移除当前余额对家庭总余额的影响；文案兼容负余额。
- 确认及请求期间禁止重复删除和并发保存；取消确认不发送删除请求。删除失败通过现有错误区域展示，成功后通知共享数据刷新并关闭对应编辑窗口。
- 新增 `DELETE /api/accounts/:id/`，成功返回 `204`；账户存在收支或任一方向转账引用时返回 `409`，提示“该账户已有收支或转账记录，不能删除。”。
- 删除接口沿用登录与 CSRF 中间件。非法、不存在及其他家庭的账户均返回 `404`，不增加管理员专属限制。
- Store 在显式事务内按家庭范围锁定账户行，持锁检查 `transactions.account_id` 和 `transactions.transfer_account_id`，确认均无引用后才删除并提交。使用与流水变更相同的账户行锁协议，避免并发写入后被外键级联删除。
- 增加 4 项真实 PostgreSQL 集成测试，覆盖删除后余额汇总、收入/支出/转入/转出引用保护、家庭隔离与认证/CSRF、等待并发流水写入后拒绝删除。

## 验证与结果

- 在独立临时 PostgreSQL 17 数据库执行 `go test ./internal/api -run '^TestAccountDelete' -count=1 -v`：4 项测试全部通过，没有跳过。
- 执行 `go build -o /tmp/hb-account-delete-server ./cmd/server`：通过。
- 执行 `npm run build`：TypeScript 检查与 Vite 生产构建通过；构建提示部分产物超过 500 kB，未在本任务中调整分包。
- 启动实际 Go HTTP 服务，使用真实会话 Cookie 和 CSRF 请求验证：负余额且无流水账户删除成功、重复删除返回 `404`；转出与转入账户删除均返回 `409`，账户列表、流水及总余额保持不变；缺少 CSRF 返回 `403`；移除关联流水后账户可删除，汇总恢复预期。
- 未运行全量回归测试；未使用浏览器验证页面外观或交互，界面实际体验需人工确认。

## 兼容性与迁移

- 无数据库迁移，不改变现有账户余额、流水和统计计算方式。
- 仅允许删除没有任何收支及转账记录的账户。有流水的账户不会被隐藏或级联删除。
- 无流水账户也可能有手动设置的余额；删除将从家庭总余额中移除该余额。正余额删除后总额减少，负余额删除后总额增加。
- 本次保护位于应用事务写入路径；既有账户外键仍保留原级联规则，直接手工执行数据库删除不属于此接口的保护范围。

## 部署补充：账户弹窗提示请求方法不允许

### 原因与处理

- 用户反馈账户编辑弹窗显示“请求方法不允许。”；该弹窗同时承载保存和删除操作，截图本身不能区分触发动作。
- 检查确认前端账户修改使用 `PATCH`、删除使用 `DELETE`，当前后端源码均已注册对应路由，无需修改接口契约。
- 对运行服务发送不带 Cookie 的请求：`PATCH /api/accounts/1/` 返回 `401`，`DELETE /api/accounts/1/` 返回 `405` 且 `Allow: PATCH`。确认运行中的旧后端尚未包含账户删除接口，而非当前源码缺少路由。
- 更新前已通过 `pg_dump --format=custom` 备份现有数据库，并通过 `pg_restore --list` 检查备份目录。备份保存在用户私有状态目录的 `backups/2026-10-30-account-method-repair.CwpJfV/household-bills.dump`。
- 使用 Go 1.26.10 重新构建部署二进制 `backend/household-bills`，执行 `systemctl --user restart household-bills`，服务状态为 `active`。未更改源码、接口方法、服务配置或数据库结构。

### 本次验证

- 重启后不带 Cookie 的 `PATCH`、`DELETE` 请求均返回 `401`，证明均已匹配受认证保护的路由；不支持的 `GET` 返回 `405`，其 `Allow` 已包含 `PATCH, DELETE`。
- 所有路由探针均未携带会话凭据，不会进入账户写入处理器，未修改或删除真实账目。
- 本次为部署版本修复，未新增测试、未重跑集成测试，未执行已登录账户的真实修改/删除或浏览器交互验收。前述功能实现验证记录保持不变。
