# 统计日历与日明细

## 背景与目标

统计导航中的“日历”此前仅为禁用占位。本次将其完成为可用页面：上方显示月历，下方显示所选日期的流水明细。

## 实际变更

- 新增 `frontend/src/views/CalendarView.vue` 和 `/statistics/calendar` 登录后路由，启用侧栏、导航抽屉中的“统计 → 日历”入口。
- 手机抽屉保留统计分组，避免底部“统计”只进入报表而无法访问日历；总览、流水仍由底部导航提供。
- 月历按周一至周日排列，默认选中今天；支持月份选择、上月、下月、回到今天，以及今天与选中日期标记。切到其他月份默认选中该月 1 日，切回当前月选中今天。
- 月历使用既有月汇总接口的 `daily` 数据展示每天收入、支出；金额保留两位小数，窄屏省略超宽部分，完整金额保留在日期按钮的说明、悬停提示和选日后的明细合计中。
- 下方以同一天作为 `start`、`end` 调用流水接口，包含当天零点至末秒的记录。转账显示在日明细中，但不计入月历收支金额。
- 复用 `TransactionList` 的桌面表格、手机卡片和编辑、删除功能。数据变更后刷新月历、选日流水与账户快照。
- 月汇总、单日流水、账户快照分别管理加载、错误与重试；账户快照不可用时禁用编辑。切换日期、月份时用请求序号与查询日期校验丢弃过期响应，避免旧明细出现在新日期下。
- 更新 README 的简短功能介绍；不改写此前报表记录中的历史范围说明。

## 验证与结果

验证使用既有 Go 二进制、真实 PostgreSQL 中独立创建的临时 schema 和临时账本，通过 Vite 及浏览器访问真实接口；未修改原有业务表。

- `frontend/` 下执行 `npm run build`：类型检查与生产构建通过。Vite 提示部分产物超过 500 kB，此项不是构建失败，本次未调整打包策略。
- 浏览器验证当天零点收入 `1234.56`、末秒支出 `78.90`、当天转账 `200.00`：选中该日得到 3 笔，收支合计不包含转账；次日零点的 `9.99` 只在次日出现。
- 验证仅转账日、无流水日期、2024 年 2 月 29 日，以及 2025 年 12 月与 2026 年 1 月的前后月切换。
- 在日明细实际编辑支出为 `88.88`，观察月历与日合计同步更新；删除该笔后，日明细变为 2 笔，月历当日支出变为 `0.00`。
- 分别注入月汇总、流水、账户接口的临时失败响应，观察错误提示；点击各自重试后恢复真实数据，账户恢复后编辑重新可用。
- 延迟前一个日期的真实请求响应，连续切换到另一日期；前一个响应到达后页面仍保留最后选中日期的数据。
- 检查 320、390、760、1280 像素视口：月历保持七列，页面无横向溢出，日明细位于月历下方，月份选择与回到今天按钮正常排列。验证 Enter 选日、手机抽屉中报表与日历往返导航。
- 使用 Go 服务加载生产构建，直接访问 `/statistics/calendar` 并选日成功；该轮浏览器未记录页面脚本错误。
- 已查看桌面和手机页面截图。验证环境缺少中文字体，截图中文字显示为缺字方框；中文文案以浏览器 DOM 与可访问名称检查，未据此确认中文字体实际渲染效果。
- 未运行后端回归套件或 Android 构建：本次未修改后端、数据库迁移和 Android 源码。未新增前端测试框架或永久测试脚本。

## 兼容性与迁移

- 无新增 API、配置或数据库迁移；沿用既有家庭隔离、登录、CSRF 和金额协议。
- `/statistics` 与手机底部“统计”仍默认进入报表，日历作为同级统计页面从导航菜单进入。
- 需重新构建并部署前端资源；无需迁移现有业务数据。
