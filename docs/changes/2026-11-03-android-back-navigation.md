# Android App 分层返回导航

## 背景与目标

原来的系统返回只判断 WebView 浏览历史，无法识别页面中的弹窗和内部子页。实际在 Android API 35 模拟器复现：从总览打开全屏记账后按一次系统返回，直接退到总览，而不是先关闭记账弹窗并停留在流水明细。

目标是让返回键按当前界面层级逐步返回，避免越过日期面板、分类编辑或删除确认框。

## 实际变更

- Android 系统返回先处理原生对话框、设置页和错误页，然后通过 `evaluateJavascript` 调用页面的 `window.__hbBack()`；页面没有该入口时保留原有 WebView 历史后退逻辑。没有新增 JavaScript 调用原生的接口。
- 新增页面返回层栈，按实际打开顺序只处理最上层，并在关闭、卸载时释放；沿用各组件保存、删除、上传等忙碌状态下的关闭限制。
- 覆盖导航抽屉、账户菜单、账户/成员/个人设置/记账弹窗、子分类选择、分类管理内的编辑与操作子页，以及报表的大类、二级分类、流水明细层级。
- 记账日期、账户及归属选择面板，账户归属下拉框和报表日期/筛选面板优先收起，不关闭外层表单。使用 Element Plus 的可见性事件和公开关闭 API，不模拟 Escape，不通过 DOM 查找决定返回层。
- 三处删除确认复用返回取消逻辑，取消不会执行删除，也不会让调用者一直停在等待确认状态。
- 没有弹层时返回有效的站内上一页面；没有有效上一页面的非首页回到总览。总览没有上一页面时退出，登录页直接退出，避免后退到受保护页面再跳回登录的循环。首页存在有效历史时仍能回上一页面。
- 原生询问期间合并重复返回请求，切换服务器或销毁 WebView 时使旧回调失效。
- Android 版本调整为 `1.0.5`（`versionCode 6`）。

## 验证结果

使用独立 PostgreSQL 验证库、真实后端、Vite 页面及 Android API 35 模拟器；未使用业务 API 模拟响应。验证数据未写入项目源码。

### 构建

- 最终 `frontend/` 下 `npm run build` 成功，包含 TypeScript 检查和生产构建。Vite 仍提示部分产物超过 500 kB，本次不调整打包策略。
- `nix-shell --run 'android/gradlew -p android --offline --no-daemon --console=plain :app:assembleDebug'` 成功，生成 `android/app/build/outputs/apk/debug/app-debug.apk`。有既有的弃用 API 和 `aapt2FromMavenOverride` 实验性提示。
- 首次在线 Android 构建在 Gradle 下载/初始化阶段超时；依赖缓存可用后改用上述离线构建成功。

### Android 实际运行

在独立的 API 35 AVD 安装 Debug APK成功，启动、设置验证服务器并真实登录后，用 `adb shell input keyevent 4` 验证：

- 日期面板返回只收面板，全屏记账保留，未保存金额 `12` 保留。
- 子分类返回只收子分类，金额保留。
- 分类编辑先由系统收起软键盘，再返回分类管理；继续返回到外层记账，金额保留。截图确认外层表单和金额仍可见。
- 再返回只关闭记账弹窗，仍在流水明细页；下一次返回才回上一个页面总览。
- 总览的账户菜单打开时返回只关闭菜单；总览没有上一页面时返回到 Android 桌面。

### 浏览器真实页面

- 导航抽屉返回后关闭且当前账户页面不变。
- 账户删除确认返回取消，外层编辑弹窗保留；再次返回关闭编辑后，真实 `/api/accounts/` 查询确认账户仍然存在。
- 报表流水明细 → 二级分类 → 大类逐级返回，始终留在报表路由；小类视图返回大类。
- 资金账户返回实际上一页面报表。
- 直接进入无有效上一页面的资金账户页，返回总览；总览根页面返回 `exit`。
- 退出登录后页面返回 `exit`，不回退到受保护路由。

未执行：真机、API 26–34、手势模式的独立交互验证、全部选择器和全部忙碌状态组合、全量后端回归或 Android 单元测试。前端没有配置自动化行为测试框架，本次以真实页面和模拟器交互验证为准。正式签名 Release 发布结果见下节；本轮未在设备上重新执行正式包覆盖安装。

## 兼容性与部署

- 完整的新返回行为需要同时部署本次前端产物并安装新版 APK；只更新网页不会改变旧 APK 的系统返回入口。
- 新版 APK 连接尚未升级的网页时回落到原有浏览历史返回，不承诺旧网页也能识别弹层。
- 未修改数据库结构、会话协议、API 或服务端业务逻辑，无数据库迁移要求。
- 同时保留 Debug 验证包和正式签名 Release 包；用户升级应使用正式发布包。Debug 与正式包签名不同，不能混用覆盖安装。
