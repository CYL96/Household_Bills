# 流水页按筛选显示支出与收入合计

## 背景与目标

根据用户提供的手机截图，在月份/筛选栏下方、流水列表卡片上方加入支出和收入统计。合计跟随当前有效筛选，覆盖全部匹配流水，不将转账计入收入或支出；不改变现有列表或记账流程。

## 实际变更

- 流水页新增紧凑双列汇总栏：左侧「支出合计」使用支出色，右侧「收入合计」使用青绿色。与现有纸色卡片和金额样式一致，手机上保持两列，大金额允许换行而非截断。
- 新增认证接口 `GET /api/transactions/totals/`，返回 `{"income":"0.00","expense":"0.00"}`。月份、起止日期、账户、类型、关键词及重复分类参数的解析和 SQL WHERE 条件由列表与统计共同使用，避免筛选口径漂移；家庭身份始终来自登录会话。
- 汇总在 PostgreSQL 中按整数分计算，`SUM(bigint)::text` 经现有 `parseAggregateCents` 检查并在 API 边界用 `money.Format` 输出两位十进制字符串。空集为零，转账永不计入收支；只筛选转账时两项均为零。
- 前端列表与合计使用同一个筛选快照和现有请求序列号，搜索防抖期间立即清除旧合计，旧请求晚到不会覆盖新筛选。继续响应现有 `dataVersion`，保存、编辑和删除后的数据刷新会同时更新合计。
- 列表与统计独立处理加载结果。统计未成功加载时显示 `—`，失败时显示错误和重试入口，不冒充零金额，也不隐藏已成功加载的流水列表。
- 现有列表 API 仍返回数组，当前没有分页；未引入分页、归属筛选、数据库迁移或新依赖。README 仅更新用户功能概览。
