# 流水明细分类名称前显示图标

## 背景与目标

流水明细此前只显示分类名称。本次在名称前显示对应分类图标，保持桌面表格与手机卡片一致。

## 实际变更

- 修改 `frontend/src/components/TransactionList.vue`，在桌面分类列及手机卡片分类标题前渲染图标，使用现有图标库及颜色变量。
- 收支分类从当前家庭的响应式分类快照读取显式图标，通过现有 `entryMatchesName()` 匹配当前名称、默认名称及历史名称；不新增网络请求。
- 未配置显式图标时沿用内置名称映射，无法匹配时显示通用标签；账户转账使用内置双向箭头。
- 图标固定为 14px，保留名称与原有收支类型提示；装饰性图标设置 `aria-hidden`，避免重复朗读。
- 流水页和报表下钻复用该组件，因此共享此展示逻辑；未修改报表分类统计行。

## 验证与结果

- 在 `frontend/` 执行 `npm run build`：TypeScript 检查与 Vite 生产构建通过。Vite 提示部分产物超过 500 kB，没有构建错误。
- 使用 Chromium 打开实际构建的 `/transactions` 页面，通过浏览器请求拦截提供临时认证、分类及流水夹具；没有写入现有数据库。
- 桌面视口 1366×900：检查五笔流水的 DOM，确认内置餐饮图标、历史名称对应的自定义咖啡图标、未配置分类的通用标签、收入分类显式配置的钱包图标及转账双向箭头均位于分类名称之前，并截屏检查布局。
- 手机视口 390×844：同样五笔流水均显示对应图标，断言图标位于名称之前且宽度为 14px，并截屏检查卡片布局。
- 浏览器环境缺少中文字形，截图中文字显示为缺字方框；分类中文内容通过 DOM 确认，图标正常显示。未验证真实字体环境中的中文排版。
- 未运行后端测试，未进行真实登录/数据库端到端验证，未单独打开报表下钻页面；本次没有修改后端或持久化逻辑。

## 兼容性与迁移

不涉及 API、数据库、依赖或数据迁移。现有分类名称、金额、编辑与删除行为不变。
