# 按参考图清空并重建支出分类

## 背景与目标

用户要求参考截图调整分类，随后明确清除现有分类后重新建立。本次只重建截图展示的支出分类；收入分类、历史交易与账户余额不变，不将旧支出分类映射或合并到新分类。

## 实际变更

- 默认支出分类改为 11 个一级分类、72 个二级分类，保持截图中的顺序：餐饮、宝宝、购物、住家、医疗、交通、人情往来、学习、美妆、娱乐、旅游。
- 系统以名称识别分类，同一收支类型内不允许重名。因此宝宝下的医疗、娱乐、学费、书籍、日用品分别命名为「宝宝医疗」「宝宝娱乐」「宝宝学费」「宝宝书籍」「宝宝日用品」；其他名称按截图建立。
- 默认数据物化时写入父级引用；后续自定义改名、停用、图标、删除和排序仍沿用现有机制。追加缺失内置子项时解析父级当前名称，父级不存在或已是二级分类时不创建悬空或三级关系。
- 为全部 83 个分类提供项目内置图标映射，保留旧名称的历史账目图标。
- 新增 `0010_rebuild_expense_categories.sql`，一次性替换所有已有家庭快照中的支出分类，清空旧支出删除标记；收入 JSON 保持不变。分类版本递增，使迁移前打开的旧草稿不能覆盖新设置。
- 不再从旧浏览器配置导入支出分类，避免旧分类重新出现；仍可迁移旧收入设置，旧浏览器键不删除。
- 更新 README 的默认分类使用说明。

## 验证与结果

- 在独立、可丢弃的 PostgreSQL 17 集群内建立迁移 0001–0009 的结构及两个家庭的旧分类、收入自定义、账户和历史账目，执行迁移 0010：两份支出快照均被替换，收入 JSON、账户及历史交易逐行比较保持不变。
- 使用临时 Go 程序调用真实 `store.Open`、`GetCategorySettings`、`ReplaceCategorySettings` 和 `Migrate`：读到 11+72 分类树，名称唯一、父级有效，旧分类不再出现在选项中；旧版本保存返回分类冲突；重建后新建自定义分类，再次执行启动迁移不会清掉该自定义项。
- 使用 Vite SSR 执行实际前端模块：默认树与数据库迁移生成的 83 项逐项一致；默认树重复物化稳定；父级改名、停用和自选图标得到保留；删除父级不会重新添加其缺失子项；已移到二级的父级不会产生三级；全部新分类均命中图标映射；收入默认值不变；旧浏览器支出不再被读取，收入仍可导入。首次执行发现公共交通图标引用了不存在的 `Bus`，修正为已有 `LucideBus` 后通过。
- `frontend/` 执行 `npm run build` 通过，包含 TypeScript 检查与生产构建；Vite 仍报告大于 500 kB 的产物体积提示。
- 尝试构建完整后端时，工作区同期变动中的 `backend/internal/api/categories.go` 存在将 `nil` 用作字符串返回值的编译错误，构建未通过；该文件不属于本次改动，未修改，也未将后端整包构建记为通过。迁移与 store 烟测不依赖该 API 文件，已单独完成。
- 未运行全量回归测试，未执行页面视觉或浏览器交互验收；HTTP 分类接口未完成运行验证。临时烟测程序已清理。

## 兼容性与迁移注意事项

- 部署包含本次迁移的后端并启动后，现有家庭的支出分类设置会一次性全部替换，包括自定义、排序、图标、停用及删除状态；需要保留旧设置时，应在升级前备份数据库。
- 不删除、不重分类历史交易。历史交易仍显示原分类文字，统计仍按原文字归组；本次没有为新分类补充旧分类别名，因此新分类的查看账单不会自动包含已清除的旧名称。
- 收入设置不重置。新家庭直接使用新默认树；已有家庭迁移后仍可继续自定义，后续启动不重复清空。
