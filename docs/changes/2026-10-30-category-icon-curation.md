# 按当前分类精简并统一图标库

## 背景与目标

用户要求根据当前分类推断并优化图标库，允许使用网上的新图标，删除旧图标。原选择库有 1000 个选项，包含大量与现有家庭分类无关的内容，并混用 Element Plus 与 Lucide 图形。本次以当前分类为依据收敛选项，统一绘制风格，不额外引入联网加载或依赖。

## 实际变更

- `frontend/src/utils/categoryIcons.ts` 从 1000 个选项精简为 85 个精选选项，删除无关旧选项、冗余导入及旧分类名称映射。
- 分类图形统一使用已安装的 `@lucide/vue`，保持 24×24 画布、`currentColor` 描边和一致的线条风格；项目其他界面的 Element Plus 图标不在本次范围内。
- 分组改为通用、餐饮、宝宝、购物、住家、医疗、交通、人情往来、学习、美妆、娱乐、旅游、收入，共 13 组。
- 完整覆盖当前 83 个支出名称、7 个收入名称及账户转账；支出和收入共享「红包」，因此合计 90 个不同名称。语义相同的分类复用图形，例如牛奶／奶粉、书籍／宝宝书籍、医保／汽车保险；奶茶咖啡与咖啡豆分别使用杯子与豆子，医疗与保险分别使用医疗和盾牌语义。
- 在选项上直接声明适用分类名称，由同一份声明生成名称到图标 ID、ID 到组件的映射；删除独立的旧组件映射表和逐次线性扫描，也不再维护重复的 ID 白名单集合。
- 新增 `categoryIconId()`，统一执行「有效显式图标 → 当前名称匹配 → 通用标签」规则。分类编辑器直接使用该规则确定选中 ID 和分组，删除按组件引用反查 ID 的逻辑，避免共享图形选错选项。
- 更新 README 的图标使用说明。未新增第三方来源、依赖或资源；保留现有 Lucide／Feather 许可文件。

## 验证与结果

- 使用 Vite SSR 加载真实模块，调用 Vue 服务端渲染器逐一渲染全部 85 个图标，均生成包含图形节点的 SVG，具有 24×24 画布、`currentColor` 描边和线宽 2。
- 检查全部 90 个当前名称均解析到选择库中的非通用图标；图标 ID 唯一、分组有效、ID 格式符合后端要求。
- 验证有效显式选择优先、移除的 ID 按名称回退、未知自定义及旧分类名称回退通用；`constructor`、`__proto__` 等名称不会误命中原型属性。
- 用包含已移除 ID 与保留 ID 的临时响应执行真实 `getCategories()` 解析路径：已移除 ID 被丢弃，现有名称、层级及收入数据仍保留；保留 ID 不变，产生的草稿通过实际 `prepareCategoryPreferences()` 校验。该项是前端响应解析烟测，不是后端 HTTP 集成测试。
- `frontend/` 执行 `npm run build` 通过，包含 `vue-tsc --noEmit` 与 Vite 生产构建。最终入口 JS 为 1145.53 kB，gzip 371.83 kB；构建仍有部分 chunk 超过 500 kB 的提示，未抑制警告或额外调整分包。
- 未运行后端测试：本次没有修改后端、API 协议或数据库。未进行浏览器页面外观和交互验收；SVG 渲染验证不代表页面视觉验收。
- 临时烟测脚本已清理，没有新增测试框架。

## 兼容性与迁移

- 不改分类名称、归属、启用状态、排序、账目或余额；不需要数据库结构迁移。
- 仍在精选库中的图标 ID 保持有效，绘制组件统一为 Lucide。不为已移除图标建立兼容目录或保留旧组件。
- 已保存的失效图标 ID 由现有读取逻辑丢弃，当前分类按名称匹配新图标；未知自定义和已移除的历史分类名称显示通用标签，可重新选择。下次保存分类设置时，保存的是当前有效配置，而不是被丢弃的旧图标字段。
- 本次删除的是应用中的旧图标选项、映射和导入，不批量修改数据库内已有图标字段，不删除 Element Plus 等仍被其他页面使用的依赖。
