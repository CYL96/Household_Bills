# 家庭共享分类

## 背景与目标

原分类管理把分类字典按家庭与用户保存在浏览器 localStorage，同一家庭的成员、不同设备之间不能共享配置。本次将名称、两级层级、图标、排序、启停、内置来源、历史名称及永久删除标记统一持久化到 PostgreSQL，家庭所有成员共用同一套配置。

## 实际变更

### 后端持久化与 API

- 新增 `0009_household_category_settings.sql`：以 `household_id` 为主键存储一个家庭的支出、收入 JSONB 快照及递增版本；删除家庭时级联删除配置。
- 新增受认证保护的 `GET /api/categories/`、`PUT /api/categories/`，沿用认证优先于 CSRF 的中间件、尾斜杠、来源校验及不缓存响应的约定。所有家庭身份取自会话，任何本家庭成员均可管理，不能通过请求选择其他家庭。
- 尚未建立配置时，GET 返回 `initialized:false`、`revision:0` 及两个空快照，不写入默认数据；PUT 必须同时提交支出和收入，以 `base_revision:0` 创建首次配置。
- 保存为单条 SQL 原子插入或条件更新；旧版本或并发首次创建返回 409，不写入任何一类配置。成功响应返回完整快照和新版本。
- 校验名称长度、空字符、重名、必填布尔值、两级父子关系、至少一个启用的一级分类、内置来源唯一性、图标标识、历史名称及删除标记；明确拒绝可选字段的显式 `null`，但允许省略。
- 不为交易分类增加外键或存在性限制，不改写历史交易的分类字符串、查询条件或统计分组。

### 前端完整切换

- 新增分类 API 包装、线协议类型、共享偏好规范化工具及只读旧数据迁移工具；API 边界转换 snake_case，页面继续使用现有 camelCase 条目。
- 分类 store 改为家庭快照的响应式内存状态，正常读取、保存不再使用浏览器存储；登录后加载，打开记账或分类管理时刷新。账号/家庭切换和退出时清空状态，过期身份的响应不能污染新身份。
- 分类管理加载成功后再建立草稿及独立的基线版本；一次保存两种收支分类，移除旧的逐类 localStorage 写入及补偿回滚。保存失败保留草稿，409 不自动覆盖或重试。未编辑的首次“保存设置”也会建立家庭快照。
- 记账窗口显示加载、失败和重试状态；成功加载前不提供未经确认的默认候选，只有服务端明确未初始化时才显示默认模板。编辑已有账目时继续保留其原分类字符串。
- GET/PUT 响应按版本单调应用，迟到的旧快照、旧未初始化响应及较早加载失败都不能覆盖更晚的成功保存。
- 保留已有分类拖动让位动画、右侧个数、精简标题、无虚线分隔及网格末尾的 16px 加号入口。
- 根 `README.md` 的稳定使用说明改为家庭共享、跨设备读取、原子保存及冲突处理。

## 升级与兼容性

- 本次保留工作区同期引入的支出重建策略：`0010_rebuild_expense_categories.sql` 会在应用一次迁移时，将已有家庭的支出配置替换为新的内置树并递增版本，收入保持不变。它不是共享接口在每次启动时自动重置数据；迁移已经执行后，后续重启保留成员的新修改。升级前应备份已有分类配置，尤其是自定义支出。
- 与该策略一致，只有家庭尚未建立服务端配置时，才尝试采纳当前账号的旧本机**收入**配置；旧本机支出不恢复，使用新的支出模板。保留旧收入的排序、图标、层级、别名及删除标记。若没有有效旧收入，默认模板只在内存展示，首次手动保存才建立服务端快照。
- 首个成功迁移或保存建立家庭配置；同时初始化的失败方读取已建立的家庭快照，不合并或覆盖其他成员的旧字典。家庭初始化后，其他账号的旧本机配置不再参与活动数据读取。
- 旧 localStorage 键保留作备份，程序不再写入或删除它们。账户排序等其他本机偏好不受此次切换影响。
- 现有交易、账户、成员数据无需分类名称转换，历史分类与统计口径不批量改写。

## 验证与结果

所有数据库检查使用本次单独启动的 PostgreSQL 17 临时集群及独立测试、烟测数据库，不连接开发或生产数据库。

### 专注集成测试

执行 `go test ./internal/api/ -run '^TestCategorySettings' -count=1 -v`，配置专用 `TEST_DATABASE_URL`，8 个顶层分类集成测试全部通过，无跳过，覆盖：

- 同家庭跨成员读写、层级/图标/顺序/别名及删除标记持久化；不同家庭隔离。
- 首次插入、旧版本 409、真实并发更新一成一败且失败不写入。
- 认证、CSRF、来源及尾斜杠约定。
- 缺失/非法字段、名称和层级边界，以及四个可选字段显式 `null` 返回 400 且版本、两类数据均不变。
- 配置改名不改写历史交易及统计中的分类字符串。

执行后端 `go build -trimpath -o <临时目录>/server-final ./cmd/server` 通过，相关 Go 文件已 gofmt。未运行广泛后端回归套件。

### 真实运行烟测

运行实际 Go 服务并通过带独立 Cookie jar 的 HTTP 客户端验证跨成员读写、另一家庭隔离、旧版本与缺失 CSRF 拒绝、空值拒绝。观察到同期 `0010` 的一次性支出重建后，重新保存，再重启服务，确认最新共享配置及版本均保留。

通过 Node.js + Vite 加载实际前端 store、API 包装及认证代码，与上述真实服务交互；仅使用内存 localStorage/Cookie 环境和可控网络延迟、失败注入，不使用浏览器。通过的场景包括：

- 旧本机收入首次迁移，图标/层级/别名/删除默认项保留；新支出树正确建立，旧键原样保留。
- 两种分类一次保存；另一成员在独立会话中读取相同配置，其冲突旧本机数据不能覆盖家庭数据。
- 陈旧草稿返回 409，已保存配置和持有草稿均不被修改。
- 加载失败阻止保存，首次失败不暴露默认候选，重试后恢复真实家庭配置。
- 切换账号与家庭后，迟到的旧家庭响应被丢弃。
- 复现并修复“同一身份旧 GET 响应将保存后的版本回退”的问题；修复后旧成功/失败响应都不能破坏新保存，旧未初始化响应不能清空已初始化状态。
- 提取并执行组件实际 `submit`、草稿校验及保存函数，确认无编辑的首次保存仍发起完整 PUT 并建立版本 1。

冒烟脚本全部在内存中执行，未保留临时测试源码。
