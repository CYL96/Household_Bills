# 统计顶部切换报表与日历

## 背景与目标

将“报表 / 日历”的切换放到应用顶部标题栏，手机与桌面在统计模块内都能直接切换，不再依赖侧栏或抽屉的二级菜单。

## 实际变更

- `frontend/src/layouts/AppLayout.vue`：统计路由下保留家庭名称，将可见页面标题替换为“报表 / 日历”圆角分段导航。使用真实路由链接，选中项按路由名称更新，并设置 `aria-current="page"`。
- 保留隐藏的一级页面标题和原有文档标题；其他页面继续显示原来的可见标题。导航提供“统计视图”无障碍名称，支持键盘聚焦、Enter 跳转与链接的常规浏览器操作。
- `frontend/src/components/AppNav.vue`：统计折叠组收拢为单独“统计”入口，默认进入报表；删除旧的展开状态、专用图标导入及子菜单样式。日历页仍高亮统计入口，抽屉点击后照常关闭。
- 手机底部“统计”仍默认进入报表，在报表、日历两个页面都保持高亮；进入统计后通过顶栏切换页面。
- 顶部导航采用紧凑布局，兼顾菜单、用户头像和 Android WebView 中额外显示的应用设置入口。不新增页内重复切换条、缓存容器或依赖。

## 验证与结果

- `frontend/` 执行 `npm run build`：Vue / TypeScript 类型检查与生产构建通过。Vite 仍提示既有部分代码块超过 500 kB，本次未调整打包策略。
- 通过临时接口响应在 Chromium 加载实际生产构建，验证报表、日历互切，两个链接的 `href`、当前项与页面文档标题正确；未访问或修改真实账本。
- 报表切到小类后进入日历，使用浏览器后退回到报表、再前进到日历均成功；离开报表后原视图的返回层正确释放，回到报表时沿用原有的根层级初始化行为。
- 检查 320、390、600、760、960、1280 像素视口：两项顶部导航不被截断、不与右侧用户区重叠，页面无横向溢出，页面保留一个一级标题。手机底部统计项保持高亮。
- 验证普通页面“资金账户”仍显示原可见标题，不出现统计切换；侧栏只保留一个统计入口，点击可回到报表。
- 模拟带 `HouseholdBillsApp/1` 的 WebView UA，在 320px 视口确认应用设置按钮、用户区、导航和菜单不重叠；实际验证 Enter 切换、手机抽屉进入统计后自动关闭，以及顶部切回日历后的底栏高亮。
- 查看顶部区域截图，浏览器未记录脚本错误。验证环境缺少中文字体，文案及选中状态通过 DOM 与无障碍属性检查；不据此宣称中文字体渲染或 Android 真机验证通过。
- 未运行后端测试、Android 构建或广泛回归测试；未新增永久测试或测试框架。

## 兼容性与迁移

- 保留 `/statistics/reports`、`/statistics/calendar` 及 `/statistics` 默认重定向，既有链接继续可用；不改接口、认证、数据库或原有筛选、日期和账务功能。
- 两个页面仍按既有路由方式挂载、卸载，不额外保存离开页面时的临时筛选或下钻状态。
- 重新构建并部署前端资源即可，无需数据库迁移或配置变更。
