# Android 设置入口融入网页顶栏

## 背景与目标

Android 外壳的 48dp「家庭账本 / 设置」工具栏与网页自身的页面标题栏重复。按本次确认的方案，正常网页只保留网页顶栏，在头像右侧放置独立「应用设置」齿轮；不采用覆盖网页的原生悬浮按钮。

## 实际变更

- 新增 `frontend/src/components/AppSettingsButton.vue`，复用于登录后顶栏和登录页「欢迎回来」旁。入口为 44×44px 齿轮链接，具有「应用设置」可访问名称和键盘焦点样式；随网页布局排列，不设置浮动定位或独立高层级。
- 普通浏览器不渲染入口。新 Android WebView 在默认 User-Agent 后追加精确空白分隔标识 `HouseholdBillsApp/1`，前端按完整 token 检测能力，不使用宽泛的 Android/版本子串匹配。此标识只是显示提示，不承担安全校验。
- 网页使用真实链接 `household-bills://settings` 打开原生设置。原生只接受精确 URI、当前 WebView/generation、主框架、用户手势、正常网页状态、非切站期间且当前页面与已保存服务器同源的请求；无手势信息的旧字符串回调只阻断，不打开设置。没有注入 JavaScript 原生桥，也未注册可由其它应用启动的 scheme 深链。
- 正常网页与错误页不显示原生工具栏；原生设置页保留标题与「返回」，复用原有取消设置逻辑。进入设置收起键盘，原生错误页仍提供「重试 / 设置」。
- 原生加载进度条移到内容区域顶部，仅占 2dp 覆盖层，不再保留 48dp 空行；原生设置/错误状态下隐藏，异步页面加载回调不使其重新出现。
- APK 版本为 `1.0.3` / `versionCode=4`，保持包名和最低系统版本不变。个人设置、退出登录、换站清理、Cookie 与账本业务接口没有改变。
- README 同步新的操作入口和前端先行部署要求。原始外壳与更新功能历史分别见 [WebView 客户端记录](2026-10-31-android-webview-apk.md)和[服务器更新记录](2026-10-31-android-server-updates.md)。

## 验证结果

### 前端与代码审查

- `frontend/` 执行 `npm run build`，Vue TypeScript 检查和 Vite 生产构建通过；仍有超过 500 kB 的产物体积提示，未调整分包或抑制提示。
- 启动独立 PostgreSQL 17 集群和真实 Go 账本服务，使用临时数据库管理员登录验收，没有使用真实账号或修改已有账本数据。
- Chromium 实际页面验证：普通浏览器登录页与登录后均无齿轮；追加精确 App token 后登录页和头像右侧出现齿轮；相似但不同的 `HouseholdBillsApp/10` 不显示入口。
- 实测 390px 与 320px 窄屏：头像与齿轮同行，触摸区域 44×44px，页面标题仍可显示；键盘焦点具有可见轮廓；路由切换保留入口；个人设置弹窗与导航抽屉遮罩能盖住齿轮，不存在原生悬浮层抢占点击。
- 只读审查未发现受限导航、设置返回、页面可见性或进度条状态的确定性问题。

### Android 构建、签名与模拟器

- JDK 17、Gradle 8.11.1、Android SDK 35 执行 `:app:assembleRelease :app:assembleDebug` 成功，Release 附带的 lint vital 检查通过。首次 Wrapper 分发包下载超时，随后复用已有本机 Gradle 分发包及依赖缓存完成离线构建；NixOS 的 `aapt2` 通过本机命令行 `-Pandroid.aapt2FromMavenOverride=...` 指定，未写入仓库。
- 在 Android 15 / API 35 x86_64 模拟器安装原签名 1.0.2、配置隔离服务器，再覆盖安装正式 1.0.3 成功，已保存服务器地址保留。本次旧版未勾选「记住登录」的临时会话在覆盖安装后回到登录页，因此不宣称此会话跨升级保留；新版重新登录后进入设置并返回仍保持登录。
- 实际截图确认：登录页只有网页品牌与欢迎区域，齿轮位于欢迎标题旁；登录后只有网页顶栏，齿轮紧邻头像右侧。WebView 顶部从旧版屏幕坐标 y=254 提前至状态栏 Insets 后的 y=128，移除了额外的 48dp 原生栏。
- 从登录页和登录后的齿轮均能打开真实原生设置，显示版本 `1.0.3（4）` 与已保存服务器；原生「返回」和 Android 系统返回均恢复原网页。
- 实际打开个人设置弹窗并观察截图：齿轮位于遮罩下；点击其原位置不会进入原生设置。未提交资料修改或记账数据。
- 切换到不可连接的隔离端口，原生错误页显示「重试 / 设置」且无额外顶栏；进入设置再返回恢复错误页。恢复端口转发后点击「重试」，成功加载真实账本登录页。
- `apksigner verify --verbose --print-certs` 验证 APK v2 签名通过，证书 SHA-256 与既有版本相同：`4aedbbd0ea296d721d1263120fb78765bd30fd1ee8ce47c2eaad07843c6f8658`。
- 执行 `:app:publishRelease`，生成带哈希 APK 和 `android/release/latest.json`；本机与既有公网更新接口均实际返回 `1.0.3` / code 4，无需重启后端。

## 兼容性与部署

- 必须先部署配套新版 `frontend/dist/`，再升级 APK。旧 APK 不带能力标识，新前端不会显示重复齿轮，旧原生工具栏仍可使用。
- 新 APK 配旧前端时，正常网页没有新的设置入口，不能把两者作为独立可任意排序的更新。正常后端已对 HTML 使用 `Cache-Control: no-cache`，静态资源使用带哈希文件名；若反向代理或旧页面缓存未正确更新，应先在旧 APK 设置里刷新页面缓存、确认页面更新，再升级 APK。
- 本机既有服务从仓库的 `frontend/dist/` 直接提供静态资源，本次生产构建已更新该目录；没有修改原服务数据库、监听地址或进程配置。
- 不涉及数据库迁移或后端业务接口变更；覆盖升级须保持原签名。
