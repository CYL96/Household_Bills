# 移动端流水列表紧凑化

## 背景与目标

移动端原先每笔流水独占圆角卡片，完整日期、类型标签、底部分隔线和成员行重复占用空间。改为按日期分组的紧凑列表，提高手机上一屏可浏览的记录数量，同时保留原有编辑、删除和账户转账信息。

## 实际变更

- 修改 `frontend/src/components/TransactionList.vue`，仅调整不超过 760px 的移动端列表；桌面仍使用原表格。
- 按本地民用日期对相邻记录分组，保持输入顺序，不重新排序；分组标题包含年份，避免跨年记录混淆。
- 同一天按日期聚合；根据后续反馈，每笔保留独立的浅色边框与 10px 圆角，笔与笔之间增加 6px 间距，避免紧凑布局中记录边界不清。无备注流水仍为两行：分类图标、分类名与金额；时分、账户与成员。
- 有备注时追加一行，长备注单行省略；完整内容保留在原编辑界面中。长分类、账户和成员名称同样省略显示，并保留完整标题文本。
- 移除移动端圆点、重复的收入/支出标签、底部虚线及独占成员行。收入、支出仍显示正负号；转账保留明确文字标识及“源账户 → 目标账户”。金额为辅助技术保留类型标签，时间保留完整日期和秒数。
- 保留原来的左滑操作区、键盘操作、编辑禁用条件、删除确认和数据刷新链路；点击记录本身仍是收起已展开的操作区，不改变原有编辑入口。
- 未减少页面底部为悬浮按钮和导航栏预留的空间。

## 验证与结果

- `frontend/` 执行 `npm run build`，TypeScript 检查及 Vite 生产构建通过。
- Vite 提示部分构建产物超过 500 kB；本次未调整打包分块。

### 浏览器界面验证

使用真实 Chromium、中文字体和 Vite 页面，在浏览器内拦截 API 返回隔离的样例数据，未读写实际家庭业务数据。记录高度在相同的 390px 宽视口下测量，取近似值：

|记录类型|改造前|改造后|
|---|---:|---:|
|无备注|104px|54–55px|
|短备注|133px|73px|

已执行：

- 390px 手机宽度截图检查：同日共用外框、细线分隔，收支金额和转账方向正常显示。
- 320px 窄屏检查：长分类、长账户、长成员和长备注保持单行省略，页面无横向溢出；跨日、跨月及跨年标题保留完整年份。
- 页面滚动到底部后，最后一笔记录底部位于悬浮新增按钮顶部之上，仍可完整查看。
- 键盘 Enter、左方向键揭示操作区，Escape 收起；编辑入口能够打开原有编辑界面，完整长备注和带秒数的记账时间仍保留。
- 鼠标拖动及 Chromium 触摸事件分别验证左滑揭示操作区；删除按钮打开原确认框，取消后记录保留，未提交实际删除。
- 空列表显示原有空状态及重置筛选/记账入口，无流水行。
- 1280px 桌面宽度截图检查：仍为原表格布局，无移动端流水行，页面无横向溢出。

## 后续调整：加强记录间分隔

- 用户反馈同日细目过于拥挤；取消日期组共用外框，为每笔增加独立 1px 浅边框和 10px 圆角，使用 6px 网格间距分隔，不增加记录内部留白。
- 再次执行 `npm run build`，类型检查与生产构建通过；仍有构建分块超过 500 kB 的提示。
- 使用相同隔离样例数据，在真实 Chromium 的 390px、320px 视口检查并截图：相邻记录实际间距均为 6px，无横向溢出，无备注记录高度约 56px。
- 验证键盘展开左滑操作区和 Escape 收起；编辑、删除操作区仍可正常显示。此次仅调整移动端 CSS，未改交互逻辑和桌面样式。
- 本轮未执行真实后端写入、后端测试或真机检查。

## 兼容性与迁移

无 API、金额计算、日期存储或数据库变更，无需数据迁移。共用此组件的移动端报表明细同时使用紧凑布局。更新前端构建资源即可生效。
